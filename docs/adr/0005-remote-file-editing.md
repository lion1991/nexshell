# 远程文件编辑：SFTP 内存读写，扩展 0003 至远程标签

Status: accepted (2026-05-30)

## 背景

ADR 0003 把内置编辑器做成**本地**文本可编辑 + 保存，但**明确推迟**「远程 SFTP 写回」：
> 超出 0001/0002「远程只下载」范围，需临时文件 / 上传 / 冲突处理，工作量大；首版聚焦本地。

现状：
- 远程标签的文件只能上传 / 下载（`file_panel` 的 SFTP worker）；`handle_file_panel_open_in_code_viewer`
  有 `file_panel_tab_is_local()` 守卫，远程文件点开直接被挡。
- `sftp_ops.rs` 只有**磁盘↔远程**的流式传输（`put_file_stream` / `get_file_stream`），**没有内存↔远程**读写。
- 「改远程一行」要走「下载→编辑→上传」三步，摩擦明显——与 0003 解决本地摩擦的初衷一致。

## 决策

内置编辑器扩展到**远程文本文件**，读写经 SFTP **内存直读直写**，复用 0003 的编辑 / 脏标记 / 未保存保护；
远程特有的网络异步与冲突风险单独处理。不引入临时文件（区别于 0003 考虑过的临时文件方案）。

- **内存读写**：新增 `sftp_ops::read_file_to_memory` / `write_file_from_memory` / `stat_file`
  （russh-sftp 的 `File` 实现 AsyncRead/AsyncWrite，可行）。打开时读 `limit+1` 字节判超大、对已读字节嗅二进制，一次往返。
- **执行路径**：编辑器 tab **克隆**源远程 tab 的 `ssh_handle`，读 / 存 / stat 用 `open_sftp_on_handle`
  起**一次性** SFTP channel 跑异步任务（russh 多路复用），与 `file_panel` worker、源 tab 生命周期**解耦**。
  （`open_sftp_on_handle` 本就是为「worker 之外的快速操作」预留。）
- **异步保存**：远程 `Cmd+S` 乐观异步——快照当前文本→后台写，tab 进「保存中」态；成功→基线=快照 + 清脏 + notice，
  失败→保留脏 + notice。保存中仍可编辑（期间再改则脏标记自动重亮）。本地仍同步 `fs::write`，不变。
- **冲突检测**：打开时记远程 `(mtime, size)`，保存前 `stat_file` re-stat 对比；变了→弹「远程文件已被改动，覆盖 / 取消」。
- **关闭 / 退出**：单关 / 批量关的「保存」改**异步感知**（写成功才关 tab，失败保留 + notice）；
  关窗 / 退出 app 把远程脏 tab 纳入「未保存」警告（仅警告确认，不自动存——同 0003 本地）。
- **范围**：远程文本 ≤4MB 进编辑器；二进制 / 超大 → notice 提示先「下载」（系统程序开不了远程路径）。
- **数据模型**：tab 新增 `code_viewer_ssh_handle: Option<SshHandle>`（None=本地）、`code_viewer_saving: bool`、
  `code_viewer_remote_meta: Option<(mtime, size)>`；`save_code_viewer_tab` 按 handle 是否存在分叉同步 / 异步。
- **术语**：canonical 词由「代码查看器」改为「内置编辑器」（见 CONTEXT.md）；代码标识符 `CodeViewer` / `code_viewer_*` 不动（重命名纯 churn）。

## Considered Options

- **临时文件中转**（下载→编辑本地临时→上传）：能顺带让外部编辑器编辑远程，但临时文件生命周期 / 清理复杂；
  内置编辑器走内存严格更省，外部编辑器远程同步是独立大特性。否。
- **内存 + 临时文件双轨**（内置内存、外部临时）：功能最全，但把外部编辑器的文件监听回传也纳入，远超本次范围。否。
- **盲覆盖**（与本地 0003 一致，不检冲突）：最省，但**终端场景**下「编辑器开着 + 另一 pane `vim`/`echo` 同文件」
  会静默丢失（本地没有的新风险）；一次 stat 成本低，值得。改取 mtime+size。
- **校验和冲突检测**：最准（mtime 可被 `touch` 骗），但每次存重读远程全文，慢网 / 大文件贵。否。
- **保存中锁定编辑 / 失败自动重试**：前者慢网卡手；后者退避 + 重试中改动的冲突逻辑复杂。取乐观异步 + 单次报错。
- **v1 远程不给关闭「保存」按钮**（只丢弃 / 取消，提示先 `Cmd+S`）：实现最省但体验割裂。取异步感知关闭。

## Consequences

- 推翻 0001/0002/0003 的「远程只下载」：内置编辑器现对**本地与远程文本**均可编辑可保存。0003 其余约束
  （二进制 / 超大回退、reuse 单标签、行尾归一）仍适用。
- `sftp_ops.rs` 新增三个内存级 op；`open_sftp_on_handle` 从「file_panel 之外的快速操作」正式承担编辑器读写。
- 远程保存依赖 SSH 连接存活：断线时打开 / 读报「连接已断开」，保存走失败路径保留脏。**无自动重连**（与全 app 现状一致）。
- 远程保存为覆盖写，无备份 / 版本（同 0003 本地）；mtime+size 仅挡「打开后被改」，挡不住「stat 到写之间」的
  TOCTOU 窄窗（可接受，靠 git 等兜底）。
- tab 状态新增三字段；关闭 / 退出的脏检测路径新增远程分支；保存 / 关闭回调链由同步改为可异步。
- 混合行尾远程文件保存同样按编辑器 primary 行尾重建（warp 固有行为，同 0003）。
