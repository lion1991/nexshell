# 0021 SSH 主机密钥变更：终端内确认并改写 known_hosts

Status: accepted（2026-10-21）

## 背景

SSH 连接对 `~/.ssh/known_hosts` 做 TOFU 校验：未知主机自动写入，已记录但不一致则拒绝。此前不一致只落成一句断开文案，让用户自己去删 known_hosts 旧条目再重连；VPS 重装后每台都要手动处理。RDP 侧同类问题已有专门的证书变更确认页（commit 25344d7）。

## 决策

- `ssh_session::connect` 的错误改为 `SshConnectError`：密钥变更单独成 `HostKeyChanged(SshHostKeyMismatch)`，带主机、known_hosts 路径、已记录指纹与本次收到的公钥；其余仍是可读文案。
- 终端标签在连接阶段收到 `HostKeyChanged` 时，不新建页面，直接复用密码提示那套终端输入管线：清屏后列出 known_hosts 路径、已记录指纹、本次收到的算法 + `SHA256:` 指纹，按 `y` 信任并重连，按其他键按原断开文案收尾。
- 信任时调用 `replace_host_key_at`：删掉该主机的全部旧条目（等价 `ssh-keygen -R`，多主机共用一行只摘掉它的名字；`|1|` 哈希条目无法反查主机名，按「密钥与该主机已记录密钥相同」判定），再写入新密钥。只给一次机会，重连后再不一致按断开处理。
- 后台的主机概览采集（`host_overview`）不交互，继续按文案失败，等终端标签确认后自然恢复。

## 不这么做的理由

- 不做独立确认页：终端标签已有「连接中 banner + 终端内交互」的形态，密码提示就走这里；另起页面要给终端标签加 phase 与 UI，收益不够。
- 不自动信任：密钥变更可能是中间人，必须由用户看过指纹后确认。
